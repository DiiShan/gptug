## 当前结论与版本关系

先覆盖微架构、RTL 设计、协助验证、协助综合、协助后端和硅后支持的全部职责，再依据真实负担、现有工具、可验收性、消费者、复用和净收益选题。接口/寄存器整理与报告分析都是候选，不能从任一局部反例直接指定全岗位第一。

报告专题针对用户明确场景：整个 SoC 有多个大 IP，每 IP 一个 tile 独立综合；同一工艺、可能不同 corner；在不同设计验证里程碑中多轮运行。节点不是制程节点，tile 不默认是 chiplet；专题细化不代表其优先级最高。

**选题与顺序以 04 v1.2 为准；这一具体 SoC 报告场景以独立子专题为准；模型性能与可靠性测试按新增模型评估专题细化。**

## 交付及收益边界

当前提供规划、数据/规则契约、实施操作、测试设计和模板，不是已经连接 EDA/API 的产品。JSON可做语法检查，但不代表实现了语义校验器；报告专题40项测试、模型专题性能/上下文/幻觉及领域测试都未在内部环境执行。

模型评估专题的样本量、负载和服务时限是待批准计划，不是实测性能或统计精度保证。配置/记录模板是数据契约草案，不是能直接执行的压测配置。

01 中 8%/20%/29% 的整体净工时情景，以及报告专题中的 A/B/C 算例都是带假设的示例，不是承诺。确定性脚本收益与运行时 LLM 增量分开；FTE 是容量释放，不等同可减少的人数。
