# 02｜数据契约与比较规则

> v2.0 · 2026-10-10｜[入口](README.md)。只规定分析所需证据，不要求你维护综合平台。完整字段目录见 [06](06-流程分阶段实施明细表.md)。

## 1. 两次交接

| 交接 | 最小内容 | 责任 |
|---|---|---|
| 代码交付 → 综合团队 | delivery_id、版本/实际文件标识、tile/config/top、功能变化、已知限制、验证引用 | 你负责；双方确认实际采用版本 |
| 综合回包 → 你 | 对应 delivery_id、run/analysis、状态、报告与文件 hash、场景/check/stage、单位/scope、有效环境引用、缺失项 | **综合团队负责**生成；你用脚本验收 |
| 补证请求 → 综合团队 | 对象与 run、具体缺什么、原始证据、比较目的、为什么影响结论、是否需要重跑 | 你负责提问；**综合团队负责**补报/重跑和回包 |

建议回包使用 `handoff.json + reports/ + evidence-index`；已有交付系统可以直接映射，无须重建。大库、网表、数据库和调度明细由综合团队保留不可变引用，不要求复制到你的目录。散列用于识别内容，不能单独证明语义或工具执行正确。

## 2. 分层索取，不将所有字段变成首轮障碍

| 层级 | 需有的证据 | 缺失时允许做什么 |
|---|---|---|
| 接收/归档 | 文件、交付来源、对象身份；来源不明的文件隔离 | 盘点文件和缺失项，不进入正常事实集合 |
| 有效事实 | 上述＋run/analysis/check/stage、来源位置、单位、scope、完成/截断状态 | 保留可验证字段；受影响字段为 unknown/partial |
| 同条件比较 | 上述＋实际设计标识、功能范围、库/recipe、有效 SDC/周期/边界、scenario、报告口径的可审查证据 | 展示已有事实和条件差，不宣称同条件优化 |
| 节点/SoC 接受 | 上述＋批准要求矩阵、快照成员、全部必需项和跨 tile/验证证据 | 展示进度缺口，不宣称节点通过或签核 |

**综合团队负责**提供实际生效环境或正式导出/确认记录。仅“环境未变”的口头说明不等于已核验；应附配置/执行标识和可追踪来源，明确证据级别。无法独立核验时写明“团队确认，未独立复核”，不得悄悄升级为完整证据。

## 3. 核心对象与字段

| 对象 | 主键/必要信息 | 谁产生 |
|---|---|---|
| delivery | delivery_id、代码/config/function 版本、变更及验证引用 | 你 |
| tile/instance | tile/config/top/wrapper、SoC 实例、面积归属、owner | 你/集成确认；综合团队回报实际 top/config |
| milestone/requirement | 节点/版本；必需 tile/config/stage/scenario/check/report；阈值、N/A、沿用政策 | 双方及集成批准，不由 AI 自动生成正式政策 |
| run | 全局 run_id、retry_of、job、时间/时区、退出状态、实际输入、工具/build、recipe、输出设计标识 | **综合团队负责** |
| analysis | analysis_id、producer_run、design_source_run、design hash、stage/scenario/check/scope | **综合团队负责** |
| artifact | 内容 hash、原始位置、类型、格式、完成状态、访问范围 | **综合团队负责**封存；你登记接收副本 |
| metric/path | 原始/规范值和单位、状态、scope、语义/parser 版本、证据位置；路径另有起终点/clock/edge/mapping | 你的固定解析器，来源为团队报告 |
| comparison | base/head、目的、受控/允许变化项、未知项、规则版本、逐指标可比状态 | 你批准目的，脚本判定 |
| snapshot | 节点、截止时间、要求版本、精确成员、缺失/沿用/年龄、跨 tile 覆盖、批准状态 | 你的脚本候选；集成/责任人确认 |
| finding/review | 事实、假设、请求、责任人、输入版本、结论及关闭证据 | 你与综合团队分工处理 |

同次综合可供多个 analysis 复用；多个优化目标生成不同网表则须分开。重试产生新 run；重导报告不冒充新综合。旧模板缺字段时标未知，不按目录名猜补。

## 4. 有效环境与边界清单（综合团队负责提供）

实际 filelist/source 顺序、include/宏/参数、生成文件、dirty patch；工具/build 和优化选项；PDK/标准单元/宏库版本与散列、VT/dont_use；加载后的 clocks/generated clocks、I/O、exceptions、case/disabled arcs；mode/PVT/电压域、RC/寄生、clock propagation、OCV/derate/CRPR/SI/GBA/PBA；wrapper/tie-off/stub、I/O load/transition/预算参考；报告选项、Top-N、过滤、单位和精度。

你确认交付 RTL 与功能意图；综合团队确认实际运行。环境字段按指标用途要求，功耗活动和物理信息仅在相应比较启用时必需。日志、后台作业和 license 的细查仍由综合团队完成；你提出有范围的问题单，不直接扫描其系统。

## 5. 数值、证据与状态

每项保存 `raw_value/unit、normalized_value/unit、value_status、scope、evidence_refs、parser/semantics_version`。证据指向原文件 hash＋行区间或结构化 pointer；AI 摘要不是原始证据。未知/缺失为 null＋原因，observed 0 单独保留。

状态分开记录：执行、数据有效性、要求覆盖、可比性、QoR、功能验证、评审。负 slack 可是可信违例；退出码零不能推出分析有效；允许发布缺口报告不等于批准芯片通过。

| 指标 | 规则 |
|---|---|
| worst slack/WNS | 在完整非空且语义明确的端点集合，worst=min(s_e)，规范 wns=min(0,worst)；保留工具原始值与正余量 |
| TNS/违例数 | tns=Σmin(0,s_e)，违例数=count(s_e<0)，仅用于已批准完整端点/边沿口径；Top-N 不重算全局 TNS |
| Slack 差 | head−base，使用 ps/ns；不套负基线百分比 |
| 面积/计数差 | 同口径正基线可算 100×(head−base)/base；零基线百分比留空，负基线不套用 |
| 其他检查 | setup/hold/recovery/removal/gating/pulse 等独立存储，不混合总量 |
| 精度 | 区分源精度、展示舍入和业务容差；未知单位、NaN/Inf 不当正常物理值 |

上述是本方案规范，不覆盖工具自身不同统计语义；原始字段保留，差异由综合/STA 负责人确认后再转换。

## 6. 可比性：先判条件，后算差异

顺序：身份/完成状态 → 字段语义/单位/scope → 比较目的和允许变量 → 条件差 → 逐指标可比性 → 差异和门槛。

| 情况 | 默认结果 |
|---|---|
| RTL 改变，功能合同与相关环境固定 | 可观察设计变化；不要求 RTL hash 相同，也不自动证明等价/因果 |
| 同网表仅 STA corner 改变 | 时序属场景敏感性；同口径面积引用一次 |
| 综合库/优化 corner/recipe 改变 | 条件变化，不归为纯 RTL 优化 |
| 周期、SDC、边界预算变化 | 披露条件差；必要控制实验由综合团队负责 |
| 跨节点功能或要求扩展 | 成熟度对比；共同场景趋势和新增缺口分别展示 |
| 跨工具阶段/分析方法 | 分组或校准，不当普通回归 |
| parser/语义版本不一致 | 统一重解析或注明限制；不悄悄混用 |
| 单位/范围/来源或关键条件未知 | 受影响指标 insufficient_evidence，不默认可比 |

原因码沿用 MISSING_METADATA、SCENARIO_MISMATCH、FUNCTIONAL_SCOPE_CHANGED、BOUNDARY_CHANGED、SDC_EFFECT_CHANGED、TOOL_CHANGED、LIBRARY_CHANGED、STAGE_CHANGED、REPORT_SCOPE_CHANGED、TRUNCATED、PARSER_MISMATCH、BASELINE_MISSING、SNAPSHOT_MIXED。它们是内部约定，不是厂商错误码。

## 7. 快照与汇总的不变量

1. 从批准的必需集合 R 与满足集合 V 计算对应覆盖 |R∩V|/|R|；R 为空时是未配置/N/A，不是 100%。不同状态轴分别给分子/分母。
2. 失败、缺失、过期不从分母删除。新增要求不能被“共同场景趋势良好”掩盖。
3. 三种最新状态分开：最新执行、最后有效、选定结果。旧数据沿用须标来源、年龄和批准。
4. 快照成员跨不同网表/成熟度混合时明确 mixed-revision；冻结后新数据只能生成新 revision。
5. 同网表多 corner 不重复计面积；父子 inclusive 不相加；run 资源不按报告份数重复计。
6. 同端点跨场景 TNS 不无条件相加；局部 tile slack 不拼成全 SoC STA。
7. Top-N 消失不自动关闭；模糊路径映射不能冒充精确事实。
8. 相同输入、程序、规则、基线与成员应可重建语义结果；运行时间戳另存。EDA 重跑本身的变化另作实验，不承诺网表字节级复现。
9. AI 失败不改事实和告警；原始数据失败不能由 AI 填补。
10. 数据或规则纠错走新版本重算、旧结果替代/撤回和消费者通知，不直接修改历史。

## 8. 配置与迁移

[配置模板](配置模板.json)保留 `soc-qor/2.0` 的对象字段，增加可选 `collaboration` 交接说明；旧键不删除。`template_unapproved`、`publish_enabled=false` 保持。它不是 JSON Schema 或校验器，语法通过不代表工程配置获批。

只需先填本次样例所需字段，未知显式保留；程序按结论用途阻断相应差异/接受，不阻断无风险盘点。实际值及引用留内部，不能回填本公开仓库。
