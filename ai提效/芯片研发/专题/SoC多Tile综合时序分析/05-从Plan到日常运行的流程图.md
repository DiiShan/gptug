# 05｜三张图看懂建设、协作和质量控制

> v2.0 · 2026-10-10｜[入口](README.md)。当前图以文内 Mermaid 为准；此前 PNG 是历史示意，不能据其旧职责分工执行。图中模块是计划，不代表程序已实现。

## 图一：你如何把 plan 落地

```mermaid
flowchart TD
 A[你：选一个 tile 的两轮代码交付] --> B[综合团队负责：提供报告包和实际条件]
 B --> C[S0：你确认样例、交接要求和现有工具]
 C --> D[S1：AI 辅助写接收、解析、比较代码]
 D --> E[S2：脚本测试；你核对独立预期值]
 E --> F{关键事实与异常样例通过？}
 F -->|否| D
 F -->|是| G[S3：多 tile、节点、场景与快照]
 G --> H{S4：运行时 AI 有质量和净收益？}
 H -->|是| I[启用受控解释与逐次审核]
 H -->|否| J[保留仅脚本分析]
 I --> K[S5：按类型扩展、回归、可回滚]
 J --> K
```

不先开发综合调度、EDA wrapper、库管理和原生报告生成器；这些环节**综合团队负责**。你仅约定接口、提出缺口、验收分析所需证据。

## 图二：每轮跨团队工作流

```mermaid
flowchart TD
 subgraph D[你：代码交付]
 A[冻结代码版本、配置、变更和已知限制]
 end
 subgraph S[综合团队负责]
 B[确认实际采用版本；准备库、约束和场景]
 C[调度并运行综合、STA 和相关检查]
 P[导出报告、状态、有效条件及缺失清单]
 R[补报、环境调查或获批重跑]
 B --> C --> P
 R --> P
 end
 subgraph U[你：报告分析]
 E[接收验收；不直接操作 EDA]
 Q{身份与所需数据可用？}
 X[记录缺失、错包或未知条件]
 F[脚本：解析、质量检查、可比性和差异]
 G[脚本：事实、覆盖和 SoC 快照]
 H[可选 AI：假设、反证、补证建议]
 I[你审核；专业问题交对应负责人]
 J[发布带限制的分析结果和行动项]
 K[你：RTL 修复、验证、重新交付]
 E --> Q
 Q -->|否：受影响范围| X
 Q -->|是：有效范围| F --> G --> H --> I --> J
 end
 A --> B
 P --> E
 X --> R
 I -->|需补报或 EDA 实验| R
 J -->|确认需代码修改| K --> A
```

“数据可用”按指标/范围判断：部分数据有效可继续相应分析，缺口仍显示。综合团队导出失败/部分包也要登记；没有回包是待回包，不是成功。补报与重新运行分别留 revision/run 记录。

## 图三：AI 波动不改变事实

```mermaid
flowchart TD
 A[脚本固定事实、限制、证据包] --> B[AI 生成解释草稿]
 B --> C[脚本查结构、当前包引用、数字与风险项]
 C --> D{自动检查通过？}
 D -->|否| E[拒收或预算内修正；保留全部尝试]
 E --> F[仅用合格事实和限制；注明 AI 状态]
 D -->|是| G[你核设计语义；综合团队核时序与环境]
 G --> H{解释可接受？}
 H -->|否| F
 H -->|是| I[接受解释；未验证假设仍标待验证]
 F --> J[记录评审、行动、版本和成本]
 I --> J
 J --> K[需 EDA 补证：综合团队负责；不让 AI 自行执行]
```

自动检查不证明因果正确；模型一致不等于独立真值。数据失败不能走“仅事实页”伪装正常；只有已合格的事实才可保留。
