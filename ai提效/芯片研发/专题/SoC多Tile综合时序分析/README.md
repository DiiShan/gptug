# SoC 多 Tile 综合时序报告分析

> v2.0 · 2026-10-10｜职责修订版。适用：同工艺、多 IP/tile、多设计验证节点、多轮及多 corner。本文是方案，不是已运行软件。

**你的工作：交付代码、接收报告、检查比较、分析问题、反馈修改。综合运行及补跑由其他团队完成。**

| 环节 | 责任 | 你需要做什么 |
|---|---|---|
| 代码交付 | 你负责 | 提供版本、配置/功能范围、变更与已知限制 |
| 运行准备、库/SDC、综合/STA、导出 | **综合团队负责** | 约定交付要求；核对回包对应你的代码 |
| 接收、解析、质量检查、比较 | 你负责；固定脚本执行 | 审核差异、缺失项、可比性和关键证据 |
| 解释与问题反馈 | 你负责；AI 可起草 | 区分事实与假设，提出最小补证请求 |
| 补报告、复跑、环境调查 | **综合团队负责** | 提交问题单，等待正式回包，不自行启动 EDA |
| RTL 修复与再交付 | 你负责；按现有验证流程 | 修改、验证并交付新版本；重新分析回包 |

综合团队与 STA/CAD/后端的内部协作仍按公司分工。“综合团队负责”表示对你的交付接口，不取消各专业签核职责。

## 不变的底线

脚本负责可重放的事实与规则；AI 只写可拒收的解释；人负责工程决策。缺失不是零，负 slack 不一定是解析错误，同工艺不等于同条件，局部 tile 通过不等于全 SoC 签核。

原报告只读；生产 RTL/SDC/库/waiver 不由分析 agent 修改。真实报告、配置、源码和填写后的模板留在获准内部系统。模型不可用时保留合格事实；数据不合格时只能展示缺口，不伪装正常结果。

本专题不是全岗位默认第一，选题仍见[全岗位候选](../../04-全岗位首批试点选择与优先级修订.md)。旧版详细讨论可通过 Git 历史查阅；当前职责以本版为准。未执行公司 EDA/API 测试、未验证生产解析器、无实测收益。
