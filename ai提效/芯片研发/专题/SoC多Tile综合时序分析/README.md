## 适用的实际场景

整个 SoC 由多个较大 IP 构成，**每个 IP 以一个 tile 独立综合**；制造工艺相同，但分析 corner 可能不同；在不同设计验证节点和各节点多轮运行中持续产生综合、时序与相关质量报告。

这里的节点指设计/验证里程碑，不是制程节点；tile 指独立综合单元，不默认是物理 die 或 chiplet。IP/tile 配置、SoC 实例、里程碑、工具流程阶段、corner/mode、迭代、实际执行和场景分析均独立建模。

本专题详细展开不表示报告分析是全岗位默认第一。首个试点仍依据完整岗位候选、当前负担、现有工具、可验收性与净收益选择。

## 核心决策

平台应同时提供**节点进度与覆盖、同条件 QoR 差异、风险/根因证据**，而不是只输出 AI 总结或按 WNS 对 IP 排名。

数据来自原生工具导出或经过测试的确定性解析器；脚本负责单位、差异、聚合、覆盖和规则；LLM 只处理有限证据包中的解释、关联与行动建议。专业负责人保留约束、基线、预算、验证和签核责任。

## 必须明确防止的错误

同工艺被误当作同分析条件；设计验证节点与 post-route 等工具阶段混淆；把各 IP 最新文件拼成无版本的 SoC 快照；用旧成功掩盖新失败；缺失必需 corner 却显示全部通过；同网表面积按场景重复累计；Top-N 消失被当成问题关闭；把局部 tile 时序汇总说成全 SoC STA；把脚本已有收益全部归给 LLM。

以上均已对应到正文规则与验收设计，不依赖模型自行判断是否遵守。
