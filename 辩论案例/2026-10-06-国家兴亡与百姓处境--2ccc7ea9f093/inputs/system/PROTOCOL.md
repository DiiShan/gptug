# 证据驱动长程辩论协议 v3.1

设计日期：2026-10-05。本协议是设计与执行要求，不是已通过用户环境实测的效果保证。
目的：充分探索、持续对抗审查、纠错和形成可追溯结论。优先质量和任务完整性，不以最少 tokens、最少轮次或尽快一致为目标。

## 1. 唯一输入、目录和职责

日常只修改 PROMPT.md 的【辩题输入】一行。每个辩题必须从新主会话开始；同一主题的重新实验也用新会话、新 run_id。
主 agent 兼任 Runner 与 Moderator；四类原生子 agent 是 Affirmative、Negative、Fact-Checker、Judge。
主 agent 是账本唯一写入者，子 agent 返回交付。不得让多个 agent 并发改同一个状态文件。
新运行先调用 `python scripts/debate.py prepare --prompt PROMPT.md`。已收到明确 run_dir 时直接使用，严禁再 prepare。
目录为 `debates/<安全主题名--主题哈希>/runs/<时间--随机ID>/`。同题共享主题目录但不同运行不共享证据状态。禁止覆盖旧运行。
prepare 自动保存原 prompt、配置与协议快照、manifest.json、run.json、run_prompt.md，并建立 rounds/checkpoints/checks/evidence 目录。
运行开始后以 inputs 内快照为准，不重读可能已被用户改成另一主题的 PROMPT.md。维护模板与执行辩论是不同任务，禁止辩论期间自改模板。
只读共享规则、当前 run_dir 和本次明确允许的来源。禁止递归扫描所有 debates，不检索其他主题、其他实验或其他线程来补观点。

## 2. 能力预检与真实性

检查实际工具能否创建子 agent、向原线程续发任务、等待结果、读写当前运行目录及读取获准来源；记录客户端/模型/权限的可观察值，未知填 null。
必须真正创建子线程，保存真实返回的标识及可追溯事件位置。不能把引用角色文件、多段角色发言或模型自己写下的 ID 当成原生证据。
当前工具缺失时标记 blocked，保存缺失能力与恢复建议，不默默降级为单模型扮演。不要用 shell 再启动一组 Codex 会话冒充当前主会话的原生子 agent。
记录实际上下文策略；子线程可能继承父线程内容，不能宣称天然独立或严格盲评。相同模型的多个角色不是统计独立样本。
默认同时开放至多四个子线程。主 agent 不计入此上限。长期复用当前运行中的正反线程；故障时可替换同角色线程，但记录旧新映射及原因，不伪装为原线程续接。

## 3. 任务卡与论证覆盖

第一个正式回合前明确：原命题、目的、关键词、时间范围、比较基线、资源/风险约束、评价标准、来源范围、保密边界和停止条件。
用户没给出的信息明确写作假设；不能自动扩张题目，不把问题翻译后的语义变化当成用户意图。decision 默认面向决策；hypothesis 面向命题检验；competition 保留训练目标并单独评表现。
制作覆盖矩阵：每个重要维度的正方最强论证、反方最强异议、关键事实、适用边界、状态和未决动作。维度随题目定，不机械限制为三个。
对能够直接测量、计算或证明的事实，先检查原始材料和可复现结果。辩论用来审查解释、假设与取舍，不用票数代替验证。
双方必须维护主张及依赖关系。立场是审查职责，不是拒绝事实：允许让步、撤回和限定；但不得因礼貌、主持人暗示或重复出现同一观点而过早同意。

## 4. 轮数与五阶段规划

正式模式默认 planned_rounds=30、max_rounds=60、每次扩展10轮；数值是为充分讨论设置的工程起点，不宣称经验最优，也不是必须跑满。
一轮 = 正反双方各一次正式交付。调度、搜索、核查、格式修复不单独算一轮；实质性追加交锋、补充最终陈述都计轮。
阶段名称延续原稿：Foundation、Deep Clash、Evidence War、Logic Closing、Final Statements。权重默认10/20/30/30/10。
按计划总轮数分配，用最大余数法取整数并保证每阶段至少一轮；不要在多个模板手写相互冲突的边界。
30轮初始计划：R1–3 基础；R4–9 深交锋；R10–18 证据密集；R19–27 逻辑闭合；R28–30 最终陈述。
50轮初始计划仍可为 R1–5、R6–15、R16–30、R31–45、R46–50；区别是它来自参数计算而不是写死。
阶段是工作重心和资源规划，不是证据准入日历。从 R1 就核查决定性事实，不能等进入 Evidence War 才查证；发现核心漏洞可返回较早阶段。
阶段提前/延后必须记录原因和实际边界。扩展时只重排未来工作，保留已经执行的轮次、阶段和历史计划，不重写过去以伪装符合新计划。
预计剩余关键工作超过当前计划时，增加 extension_rounds，直到 max_rounds。扩展必须指向具体争点/核查，不因没有共识自动延长。
Final Statements 不应塞入未经核查的新决定性事实。出现这种事实时撤销证据冻结，重开核查/交锋；预算不足则交付明确暂定结论，而非静默跳过。
smoke 模式的2轮仅用于集成验收，不是日常默认，不执行正式质量收敛判断。

## 5. 每轮执行和发言规则

R1 在接收任一方结果前向双方分派相同任务卡与来源范围，不提前给另一方立论。双方完整返回后才交换正式论证。
之后默认每轮给双方相同的上一轮快照、相关对手主张及当前争点；两方均返回后冻结本轮状态。确有必要使用串行质询时，记录先后顺序并轮换先手，避免总让一方拿到额外信息。
每轮重点可聚焦1–3个争点，但覆盖矩阵不设永久上限；被暂缓的重要争点必须留在队列里。
双方返回：run_id、轮次、输入证据版本；本轮主张及更新；Evidence；Warrant；准确复述后的 Rebuttal；适用条件；承认/撤回；待核查事实；下一项可能改变结论的工作。
保留 Toulmin 结构，但不强求所有小型补充都写成长篇套话。常规发言可参考600–1200中文字，立论、复杂证据和阶段综合可更长，不因超出该参考范围拒绝必要信息。
不强制每轮都有新论点；有效进展包括新证据、发现范围错误、缩小主张、推翻前提、回应尚未处理的反例和明确决策条件。单纯改写不算进展。
不强制第三轮换反驳目标，也不优先追逐最新小论点。持续处理最可能改变结论的未决争点。
主 agent 不逐句重复双方发言；保存双方全文，每轮只追加主持人的争点状态变化与下一步。不能为了减少上下文丢弃原始交付。

## 6. 证据核查与纠错

按主张而非按轮数触发检索。新增、争议、可能过时且影响结论的事实必须核查；有效且适用的已登记证据可复用，但关键事实要追溯原始来源或独立复算。
不强制每轮一次搜索，不等于降低核查强度。决定性事实必须逐项有结论；每阶段核查员还须抽查正式发言，发现漏登记的重要主张。
搜索引擎只发现线索，优先读取原始文档/论文/数据/日志/计算。网页摘要、转载和其他 AI 的回答不能直接充当独立验证。
本项目默认 public_only：只能检索公开问题，不向外部工具发送私有内容、路径、产品代号或内部数据。出现内部材料时按授权来源本地处理；无安全工具则明确阻断。
保留 C（主张）、E（证据）、I（争点）三个账本。E 包含来源类型、定位、必要摘录、来源日期、访问日期、版本/工况、来源家族、取得方式、真实工具定位。避免大段复制版权材料。
C 包含文本、类型 empirical/logical/forecast/value、证据ID、上游依赖、是否决定性、支持状态、核查版本和说明。逻辑结论也要登记事实前提。
状态区分 supported / partially_supported / contradicted / unverified / disputed / not_applicable；历史资料不因年代早就自动过时；未来预测不能标成已验证结果。
证据或主张含义改变时 evidence_version 加一，检查所有受影响依赖，保留旧版本与修订原因。最终依赖的事实必须重新确认到冻结版本。
内部工程比较须核对对象、版本、约束、工况、工具与运行设置，不能把不同条件的数值变化直接解释为因果。

## 7. 长程上下文和抗虚假共识

每轮保存独立正式发言；每5轮或阶段切换时保存 checkpoint，含任务卡、核心主张依赖、争点覆盖、最强双方论证、已推翻的论据、当前条件、未决动作和来源定位。
后续输入采用相关增量+当前状态+必要原文；不能全量重灌全部历史，也不能只给主持人摘要。双方分别确认 checkpoint 是否歪曲自己的关键观点。
进入逻辑闭合阶段及每次准备收敛时，必须各完成一次“最强对手论证重建”和反转条件检查；不能拿稻草人当作已击败的反方。
核查员检查覆盖矩阵与原始发言的遗漏。重要分歧允许保留，说明它是事实缺口、预测分布、价值权重还是边界条件。
新 agent 或恢复线程必须明确当前 run_id、角色、轮次和证据版本，先读 checkpoint 再续接。不恢复其他主题或其他实验的线程。

## 8. 收敛、扩展、停止

正式模式常规收敛评估从 ceil(初始计划轮数 × convergence_start_ratio) 开始；默认 R12。不得因后续扩展把这一起点不断向后移动。
同时满足以下条件才可按“实质收敛”结束：重要维度已覆盖；最终依赖的关键事实完成核查或被明确条件化；最强异议得到实质回应；双方完成反向论证检查；连续 stable_window（默认4）轮没有会改变答案、条件或关键证据状态的进展；不存在尚可执行的高价值下一步。
常规收敛可以是“稳定分歧”，不要求双方意见相同。主持人、核查员分别确认覆盖与证据闸门；不能只靠辩手自称已一致。
新证据、新反例、重要范围修订或条件变化重置稳定窗口。不能用未经定义的“新论点低于15%”代替这些检查。
即使双方同意，也要执行最强反例压力检查和最终核查。若早期已有可复现证明、题目前提被明确推翻、工具不可用或用户叫停，可例外提早结束，必须列例外理由和证据，不靠凑轮次续写。
到 max_rounds、平台额度/上下文/权限限制时停止或暂停，并区分 budget_exhausted、blocked、interrupted 与 converged。证据不足就输出条件/证据不足结论，不标成完成收敛。
本包脚本提供目录、快照、启动和事后结构验证；不是平台外部强制循环器。真正的调用/费用硬上限需平台或外部执行器，本协议不能保证单次自然语言请求一定连续跑完60轮。

## 9. 最终核查、裁决与输出

顺序：关闭重要争点或列明阻断 → 核查员最终核查 → 双方据核查修订/最终陈述 → 必要时再次核查 → 冻结证据 → 评委裁决。
主 agent 不先给评分或胜率。评委只接收冻结证据包、双方完整关键论证、修订及少数意见；不主动提供主持人结论，不宣称严格盲评。
评委提出新决定性事实或 needs_recheck 时返回核查和修订，不绕过闸门。
保存 final.md：核心答案和条件；证据链；最强异议；共识与根本分歧；撤回/修订；反转条件与第三方案；具体行动/最小验证；剩余问题；实际轮次和停止原因；核查覆盖；原生执行及隔离边界；可观察用量（未知为null）。
保存 full_transcript.md 汇集双方正式交付和主持状态变化；不包含私有思考链。原始分轮文件仍保留。
必须保存 checks/final_check.md 和 checks/verdict.md，不另造一份与评委重复的主持人裁决。
最后执行 `python scripts/debate.py validate <run_dir>`。通过仅表示已登记的结构/文件一致，不证明事实真实、抽取完整、事件没有伪造或结论质量。

## 10. 中断和权限

中断时逐轮已保存的状态不得删除。输出 checkpoint 和精确恢复指令，不能将“暂停”等同最终完成。恢复同一运行不创建新目录；重做实验必须新目录。
不自动恢复 last/latest：恢复必须给出准确 run_dir。环境版本与冻结配置改变时先说明差异，不悄悄按新模板继续旧实验。
项目配置只向本目录/其子目录生效，但全局配置、组织策略、全局 AGENTS/skills/MCP 仍可能被继承。不得声称本项目配置能阻断全部上层影响。
只读子 agent 和禁止跨目录的文字规则不等于操作系统级读取隔离；主会话仍可能有工作区写权限。强隔离须单独工作区/容器和来源白名单。
不修改 ~/.codex、系统配置、认证、组织策略或现有其他项目。安装、联网授权和 GitHub 发布不属于正常辩论自动动作。
