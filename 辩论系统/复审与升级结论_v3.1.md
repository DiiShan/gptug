# 辩论系统复审与v3.1升级结论

日期：2026-10-05。审查依据：用户提供的《优化版v2.8_5Agent辩论系统Prompt.txt》、上轮v3.0升级包、本轮明确反馈；Codex能力另依官方文档核对，见SOURCES.md。
本文件区分原稿内容、上一版问题、当前设计选择和未验证事项，不把新设计参数说成原稿已有结论或经验最优值。

## 一、总判断

原v2.8的核心方向合理：正反分工、Toulmin论证、交锋、阶段锚点、核查和面向读者的实质结论都值得保留。它并不等于“越复杂越不好”。
真正应删的是规则重复导致漂移、机械调用、相同内容多次总结、没有定义的精确分数、形式化Verified门禁，而不是必要的研究、长程交锋与独立复核。
上一轮v3.0把标准模式定为目标3轮/最多4轮，深度模式最多6轮，对这次用户希望的充分讨论过于收缩。该取舍需要纠正，不能以“为了效率”代替用户的质量目标。
本次升级不是把max_rounds从4改60而其他不动，而是补全长程状态、阶段规划、抗虚假共识、目录/会话隔离和可恢复交付。

## 二、逐项复审

| 模块 | 原v2.8或上一版情况 | v3.1决定 |
|---|---|---|
| 五类职能 | 正反、主持、核查、评委；Runner另有一份规则 | 保留五类职能；主会话合并Runner与主持，四个原生子角色 |
| 立场纪律 | 原稿要求百分之百坚持、永不让步 | 保留强对抗，但事实优先；允许撤回错误，禁止为和谐过早认同 |
| 论证结构 | 原稿用Claim/Evidence/Warrant/Rebuttal | 保留，加边界、依赖和改判条件，不为小补充强制长篇套话 |
| 轮数 | 原稿50轮上限且允许提前收敛；v3.0默认3–4轮 | 默认规划30、最多60、每次可扩展10；不是必须跑满 |
| 五阶段 | 原稿固定R1–5/R6–15/R16–30/R31–45/R46–50 | 沿用阶段含义，按总轮数和权重生成，记录实际偏移 |
| 核查时机 | 原稿评委裁决后才统一核查 | 决定性事实随时核查，最终裁决前必须闭环 |
| 搜索配额 | 原稿每人每轮至少一次 | 改为逐项关键事实触发；不减少必要核查 |
| 证据真实性 | 有Verified标签即通过 | 来源定位+主张支持关系+核查版本；工具事件另查真实性 |
| 反驳目标 | 原稿优先最新、第三轮换目标 | 按决策影响和未解决程度排序，不机械换题 |
| 新颖度 | 原稿每轮必须新论点 | 允许修正、反例检验和范围澄清；禁止复述充数 |
| 收敛 | 原稿新论点率低于15%；v3.0连续两轮无进展可停 | 覆盖、证据、最强异议、反向论证和四轮稳定共同判断 |
| 长程上下文 | 原稿阶段摘要；上一版偏短程 | 分轮全文+版本账本+阶段锚点+双方确认摘要完整性 |
| 主持与评委 | 原稿两份相近的评分/结论 | 主持只整理状态，评委做一次实质裁决 |
| 独立性 | 原稿多个文件引用被称作true multi-agent | 实际原生工具事件验收，不把角色文本当子线程 |
| 目录管理 | 原稿每个辩题生成整套角色文件 | 固定规则项目复用；每题/每次run独立输入和输出 |
| 单主题入口 | 原稿需生成后再激活，上一版仍需填多个参数 | 一个PROMPT.md主题输入；自动prepare和启动 |
| 配置作用域 | 上一版说明不够集中 | 完整独立项目、项目级配置、无全局安装；解释继承边界 |

原稿定位：角色L90–96；目录与重复文件L124–197；true multi-agent断言L218–240；阶段与收敛L345–375；上下文L378–386；核查顺序L407–414；搜索门禁L838–854；永不让步L992–995/L1155–1158；Toulmin L1024–1030；机械反驳L1079–1096；核查分类L1421–1429。行号对应用户上传的原始文本索引，不是本仓库新协议行号。

## 三、充分讨论需要什么

“该消耗就消耗”意味着关键议题值得多轮追问时继续；资料不足但仍有可执行核查时继续；新反例改变了结论时重开，而不是为了显示完成强行结束。
不意味着双方没有一致就无限继续，也不意味着每轮都重复五份长发言。去除的是重复劳动，不是有效的角色独立性。

### 1. 计划轮数驱动的五阶段

采用原稿同样的10/20/30/30/10权重，按计划轮数分配；整数取整由程序统一处理。

| 计划总轮数 | Foundation | Deep Clash | Evidence War | Logic Closing | Final Statements |
|---|---|---|---|---|---|
| 20 | R1–2 | R3–6 | R7–12 | R13–18 | R19–20 |
| 30（默认） | R1–3 | R4–9 | R10–18 | R19–27 | R28–30 |
| 50 | R1–5 | R6–15 | R16–30 | R31–45 | R46–50 |
| 60 | R1–6 | R7–18 | R19–36 | R37–54 | R55–60 |

这些是起始规划，不是只有到了某轮才允许查证。证据必须从第一阶段就可进入。发现决定性漏洞可以退回前一类工作；扩展时只重排未来阶段，不改写过去轮次。
默认30/60是匹配长讨论需求的工程起点，不是“30轮科学最优”。用户可以在一次性部署时改成50/80等组合，日常仍只改主题。

### 2. 收敛不只看重复率

正式默认R12开始常规评估，而不是R2便趋向收尾。要覆盖全部重要维度、核查关键事实、回应最强异议、完成反向论证检查，并连续4轮没有会改变答案或适用条件的变化，且没有可执行的高价值下一步。
稳定分歧也可以收敛。纯价值排序差异可能没有唯一答案，不应让模型无限辩到其中一方投降。
早期出现可复现证明、命题前提明确错误、工具阻断或用户终止可以例外结束；例外要有明确理由/依据。不能为了满足12轮继续讨论已被直接证明的事实。
新的关键证据、反例或边界变化重置稳定窗口。达到平台限制或60轮上限时可交付暂定答案，但明确是预算耗尽，不伪装成已充分收敛。

### 3. 防止长程退化

每轮保存双方正式全文；每5轮及阶段切换保存checkpoint。关键旧证据按需重读，不用主持摘要永久替代原文。双方检查阶段摘要是否遗漏或歪曲自己的最强论点。
阶段中让核查员检查未登记主张，而不只审核主持人挑选的账本条目。否则主持人漏掉决定性事实，验证器再严格也无法发现。
首轮尽量独立分派；后续轮次双方使用同一证据版本和上一轮输入。需要串行质询时记录并轮换先手。
结束前分别重建对手最强论证、列明什么事实会导致自己改判。允许事实纠错，但不把“大家都说一样”当外部证据。

## 四、仍保留的原v2.8关键修复

必须真实创建agent；读取多个角色文件不等于原生多agent。必须先核查再最终裁决；来源变化后要传播修正，不保留已失效的旧结论。
不能把“无法核实”合并成“错误”，不能把未来预测或价值判断当已验证事实，不能以未经标定的胜率和自评分制造客观精确感。
这几项不会因用户希望更长讨论而回退；长讨论更需要这些约束。

## 五、项目使用方案

固定系统文件只在独立辩论项目维护，不放全局目录。用户每次只编辑PROMPT.md第一行，启动脚本读取主题、生成安全主题目录和新run、冻结输入，然后新建Codex主会话。
不把“唯一编辑操作”误写成“软件完全不需要启动、认证或权限确认”。用户仍通过固定命令或聊天入口启动。
同主题再次运行也创建新run，不自动读取旧实验，避免自证循环；中断恢复使用准确旧run_dir，不用全局latest或resume --last。
单主题内仍是一个主对话组织多个子agent，节省手工转发和窗口切换；并不宣称只消耗一次模型调用。

## 六、隔离范围和不能承诺的事情

独立目录解决文件归档，不能清除旧主会话上下文。因此不同辩题必须新会话，默认启动器自动做到这一点；不要从旧题fork。项目关闭自动记忆读写，并要求不加载其他题目文件。
项目局部配置不会被本包安装成其他项目的全局默认，但本项目仍可继承用户配置、上层AGENTS/skills/MCP和组织策略。授权模型服务与认证不会被本包重新配置。
同一工作区内的“只读当前run”主要是规则和脚本路径约束，不是系统级不可见。严格隔离须每题独立受限工作区/容器和来源白名单。只读子agent也不自动等于强盲评。

## 七、工程交付与未验证项

本次交付包含可复制项目、完整配置和提示词、启动/目录/输入快照程序、阶段计算、恢复入口、最终结构验证及合成单元测试。
程序不是平台外强制调度循环。真正的spawn/send/wait由Codex执行，本环境未安装Codex，不能声称已经在用户账户、特定模型或内网网关跑通，也没有质量提升或费用节省的实测比例。
验证记录分静态配置/脚本合成测试与真实多agent烟雾测试；后者按SMOKE_TEST.md在实际环境确认。
下一轮效果评估应比较同一批任务的事实正确性、遗漏、对错误的修正、证据可追溯性和结论可执行性，再记实际成本。不用轮数、字数或模型自评作为质量证明。

## 八、结论

v3.1的目标是“该讨论的讨论充分、该核查的独立核查、该复用的规则统一复用、不同题目的状态互不混入”。
它既不回到v2.8的机械50轮脚本，也不延续v3.0的默认短程方案；保持五类职能和五阶段思路，升级为总轮数可规划、状态可复核、错误可传播、目录可恢复的长程系统。
